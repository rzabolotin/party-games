# Костёр

Офлайн-карточки с вопросами для вечеринок и походов: «Кто из нас скорее всего…», «Что бы ты выбрал», «Я никогда не…». PWA на Nuxt 4, без бэкенда — всё хранится в localStorage, после первого открытия работает без сети.

## ⚠️ Перед походом

Приложение кэширует себя только при открытии **онлайн**. Чтобы не остаться в лесу без вопросов:

1. Открыть приложение по HTTPS-адресу, дождаться загрузки списка колод.
2. Добавить на экран «Домой» (Safari: «Поделиться» → «На экран Домой»).
3. Закрыть, включить авиарежим, открыть с иконки — колоды и карточки должны работать.

Если после обновления приложения что-то не так — повторить шаги онлайн: service worker подтянет новую версию сам.

## Локальный запуск

Нужен только Docker.

```sh
docker compose up dev          # dev-сервер с hot-reload → http://localhost:3000
docker compose up --build web  # прод-сборка, nginx → http://localhost:8080
```

- `dev` монтирует исходники и ставит зависимости в отдельный volume; Node на хосте не нужен. Доступен и по IP в локальной сети — удобно смотреть вёрстку и жесты с телефона.
- `web` собирает статику (`npm run build`) и отдаёт её через nginx так же, как в проде: SPA-фолбэк, `no-cache` для `index.html` и `sw.js`. `--build` пересобирает образ после изменений в коде.

Без Docker (Node 22): `npm install`, затем `npm run dev` или `npm run build && npm run preview`.

`npm run build` = проверка контента (`scripts/check-content.mjs`) → генерация иконок → `nuxt generate`. Результат — статика в `.output/public`.

## Как проверить офлайн локально

В dev-режиме service worker отключён, нужна прод-сборка:

1. `docker compose up --build web`, открыть http://localhost:8080 — `localhost` считается безопасным контекстом, service worker регистрируется и без HTTPS.
2. Походить по приложению (список → колода → пара вопросов).
3. DevTools → Application → Service Workers: воркер «activated». Включить **Offline** там же или во вкладке Network.
4. Перезагрузить страницу — приложение открывается, колоды листаются, прогресс на месте.

**С телефона по локальному IP (`http://192.168.x.x:8080`) этого не проверить:** service worker и Wake Lock требуют HTTPS или `localhost`, поэтому по `http://` с телефона видно только вёрстку и жесты. Настоящую офлайн-проверку делать на задеплоенной версии (см. «Перед походом»).

## Деплой на Cloudflare Pages

Проект в Cloudflare: **koster**, боевой адрес — https://koster-779.pages.dev (`koster.pages.dev` был занят, Cloudflare выдал суффикс). Продакшн-ветка `master`.

### Ручной деплой (как сейчас)

```sh
npx wrangler login                 # один раз: OAuth через браузер
npm run build
npx wrangler pages deploy .output/public --project-name koster --branch master
```

`--branch master` = деплой в продакшн; любое другое значение даёт preview-адрес. Каждый деплой печатает ещё и уникальную ссылку вида `https://<hash>.koster-779.pages.dev` — это снимок именно этой сборки, удобно сравнивать.

Если проект понадобится пересоздать: `npx wrangler pages project create <name> --production-branch master --force`. Без `--force` wrangler пытается делегировать команду в Workers и падает; на остальных командах флаг не нужен.

### Автодеплой из GitHub (когда понадобится)

1. Запушить репозиторий на GitHub.
2. Cloudflare: **Workers & Pages → koster → Settings → Git** (или новый проект через **Connect to Git**).
3. Framework preset **None**, build command `npm run build`, output directory `.output/public`. Переменные не нужны, версию Node Cloudflare берёт из `.node-version` (22).

Дальше каждый пуш в `master` деплоится сам, остальные ветки получают preview-адреса.

### Что нужно именно для Pages

- `public/_headers` — то же, что `nginx.conf` делает локально (`nginx.conf` Cloudflare не читает): `no-cache` для `index.html`, `sw.js` и манифеста, вечный кэш для `/_nuxt/*`.
- Оболочка для каждой колоды пререндерится в файл (`nitro.prerender.routes` в `nuxt.config.ts`), иначе `/play/<deckId>` отдавался бы как 404. Splat-rewrite через `_redirects` на Pages не работает — не пытаться.

Приложение раздаётся с корня (`base = /`). Для хостинга в подкаталоге собрать с `NUXT_APP_BASE_URL=/subdir/` (переменная поддерживается и в `docker compose`).

## Контент

Колоды лежат в `app/decks/<lang>/`, по файлу на колоду, индекс — `app/decks/index.ts` (порядок в индексе = порядок в списке). Требования проверяются при сборке: ≥ 40 вопросов в колоде, каждый ≤ 90 символов, нет дублей внутри языка. Проверить вручную: `node scripts/check-content.mjs`.

Роли «Мафии» — в `app/mafia/roles.ts`: справочник из шести ролей, языковые варианты лежат внутри роли (набор ролей общий для обоих языков, в отличие от колод). Тот же скрипт проверяет и их: ровно шесть ролей, известная фракция, непустые название/tagline/описание на каждом языке и длина в пределах карты (≤ 24 / 90 / 180 символов).

## Режим «Мафия»

Раздача ролей передачей телефона по кругу: `/mafia`, вход — в группе «Другие игры» внизу главной. Экран состава (`useMafiaSetup`) хранится в `koster.mafia`, сама раздача (`app/mafia/deal.ts`) живёт только в памяти — иначе расклад партии читался бы в DevTools, а перезагрузка посреди круга означает раздачу заново. Режим не участвует в «Сбросить весь прогресс»: там только прогресс колод.
